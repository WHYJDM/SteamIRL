# Аудит неиспользуемого кода

Дата: 4 ноября 2026 года. Аудит фиксирует состояние перед добавлением игровых сессий; новые файлы сессий и модерации в его статистику не входят. Во время аудита код не изменялся и не удалялся. Найденные фрагменты сохранены и после добавления сессий и модерации. Состояния публикации и Identity-роли теперь также используются рабочим модулем модерации. U05 после добавления импортов находится на строке 61 в `App.tsx`; прежняя ссылка в таблице отражает номер до этого расширения.

## Результат и способ подсчёта

Подтверждены **5 неиспользуемых или не влияющих на результат фрагментов на 5 физических строках**:

- 3 строки целиком относятся к неиспользуемому коду;
- 2 строки содержат только отдельный неиспользуемый фрагмент, остальная часть строки нужна.

Следовательно, это **не пять строк, которые можно целиком удалить**. Считаются уникальные пары «файл + номер строки», без пересчёта компактного CSS/JSX в условные многострочные блоки. Код будущих функций в число находок не включён.

## Что намеренно не отнесено к лишнему коду

| Код или механизм | Причина сохранить |
| --- | --- |
| `ApprovalStatus.Pending`, `Rejected`, `Removed` | Используются в проверках и описывают состояния данных, необходимые для предложений локаций и модерации — US05–06, US13–14. Текущий публичный API фильтрует `Approved`; отсутствие экрана модератора не делает остальные состояния лишними. |
| Identity-роли и связанные таблицы | Основа предусмотренного разграничения прав модератора — US14. Инфраструктура Identity используется уже сейчас. |
| `ApplicationUser.CreatedAt` | Поле записывается в PostgreSQL через EF Core. Отсутствие вывода даты регистрации в текущем UI не означает, что запись не используется как метаданные аккаунта. |
| Навигационные свойства EF Core | Задействованы конфигурацией отношений, внешними ключами, отслеживанием сущностей и запросами. Прямой вызов из контроллера не является обязательным. |
| DTO, их свойства и параметры `LocationQuery` | Часть действующего JSON/query-контракта. Например, `page` и `pageSize` сериализуются, даже если frontend не читает каждое поле ответа. |
| `GET /api/me` | Есть в согласованном контракте и интеграционных тестах. То, что React сейчас восстанавливает вход через `/api/auth/session`, не делает другой endpoint неиспользуемым. |
| `WithName(...)`, `public partial class Program` | Имена входят в metadata endpoints; публичный `Program` используется инфраструктурой интеграционных тестов. |
| Миграции, `Down`, Designer-файлы и snapshot | Обрабатываются EF Core и его инструментами, в том числе при откате и создании новых миграций. Не должны оцениваться только по прямым ссылкам из приложения. |
| Регистрация `AddDefaultTokenProviders()` | Регистрация инфраструктуры Identity; отдельные сценарии выдачи токенов сейчас не реализованы. Подтверждения ненужности регистрации нет. Возможная необходимость в проверке личности связана с последующей реализацией US19; это не утверждение, что восстановление пароля уже входит в принятый backlog. |
| Ветки загрузки, ошибок, пустого ответа, пагинации и ограничения числа меток | Действующие варианты поведения. Они не становятся неиспользуемыми из-за того, что начальные данные содержат только два места. |
| npm-скрипты, Dockerfiles, nginx и GitHub Actions | Самостоятельные точки запуска и конфигурация инструментов. Их не требуется импортировать в код приложения. |

Основание для будущего объёма: [план первого этапа](first-stage-plan.md), [модель данных](data-model.md) и исходный BA-документ. Не реализованные пока сущности сессий, отзывов, фотографий и достижений описаны в плане, но их отсутствующая реализация не прибавляет строк к этому аудиту.

## Охват и проверки

- Проинвентаризированы 34 написанных для проекта файла C#, TypeScript/TSX, JavaScript-тестов и CSS: **1739 физических строк**, включая пустые строки и комментарии. Отдельно учтены 7 файлов миграций, их Designer-файлов и snapshot.
- Просмотрены маршруты и регистрация зависимостей backend, связи моделей, вызовы frontend, CSS, тестовые точки входа, конфигурация сборки, Docker Compose и CI.
- TypeScript проверен с `noUnusedLocals` и `noUnusedParameters`: замечаний нет.
- Через TypeScript Language Service проверена 31 экспортируемая декларация frontend: экспортов без ссылок не обнаружено. Учитывались также тесты геометрии карты.
- `dotnet format style --verify-no-changes --no-restore --diagnostics IDE0005`: неиспользуемых C#-импортов не найдено.
- `dotnet format analyzers --verify-no-changes --no-restore --diagnostics IDE0051 IDE0052 IDE0060 --severity info`: замечаний по указанным диагностическим правилам нет.
- Дополнительно сопоставлены CSS-классы с исходниками компонентов и динамическими именами. Подтверждённые остатки проверены вручную; состояния `hover`, `focus`, условные ветки и адаптивные правила не считались лишними из-за отсутствия в одном снимке экрана.
- Пустой декоративный элемент проверен сравнением изображений в настоящем Edge на временной странице, без изменения `App.tsx`.

Из количественного анализа собственного кода исключены сторонние библиотеки, `node_modules`, результаты сборки `bin`/`obj`/`dist`, `.git`, локальные базы, ключи и временные материалы `.local`. Локальные сценарии браузерной проверки — самостоятельные QA-инструменты, а не импортируемые модули приложения. DOCX и Markdown проверялись как документация и планы, а не как исполняемый код.

Ноль замечаний анализатора не доказывает отсутствие любого потенциально лишнего публичного метода или редкой ветки. В итог включены подтверждённые находки с понятным основанием; сомнительные случаи и работа через фреймворк не выдаются за неиспользуемый код.
