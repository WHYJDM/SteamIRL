# Площадки: реализация и проверка связей

Дата: 4 ноября 2026 года. Область: US03 — выбор активности, одобренные площадки, карта, список и сведения о месте. Игровые сессии из US04/US08–11 остаются следующим этапом.

## Изменения

- Добавлены `Location`, `LocationActivity`, конфигурации EF Core и миграция `LocationsAndActivities`.
- Связь с каталогом — многие ко многим, ключ пары уникален. Удаление используемой активности или локации не оставляет связей без родителя.
- PostgreSQL проверяет диапазоны координат, статус публикации и непустое имя. Публичные запросы фильтруют статус `Approved` до пагинации и пространственного поиска.
- Реализованы `GET /api/locations` и `GET /api/locations/{id}`. Список поддерживает активность, границы области и страницы с максимальным размером 100.
- Добавлены страницы `/#/activities/{slug}` и `/#/locations/{id}`. Карточка показывает адрес, активности, источник, дату проверки, время обновления и ограничения сведений.
- Карта использует Web Mercator и стандартные растровые тайлы OpenStreetMap. Поддержаны маркеры, перетаскивание, масштабирование, стрелки клавиатуры и возврат к Вильнюсу. Новых npm-зависимостей нет.
- Загрузка списка и меток независима. Список и карточки доступны при отказе внешнего фона; сетевые ошибки имеют отдельные действия повтора.
- Исправлена общая ссылка перехода к содержимому: она фокусирует `main`, сохраняя текущий маршрут аккаунта или площадки. Переходы между страницами возвращают прокрутку к началу.

## Проверенные связи

| Связь | Проверка |
| --- | --- |
| Location ↔ Activity | Один ID места в волейболе и баскетболе; дубли пары и ссылки на отсутствующие записи отвергаются БД. |
| Location ↔ публикация | Pending, Rejected и Removed не видны ни в списке, ни по ID, ни в запросе области карты. |
| EF Core ↔ PostgreSQL | Миграция применена к существующей базе; проверены ограничения, повторная миграция и соответствие snapshot модели. |
| Program ↔ endpoints | Маршруты зарегистрированы; неизвестные ID дают 404, неверные параметры — 400, несуществующие операции записи — 405. |
| Endpoints ↔ общий обработчик ошибок | При недоступной БД каталог, список и карточка площадки возвращают безопасный Problem Details с 503. |
| Readiness ↔ новые таблицы | Готовность проверяет таблицы локаций и связей вместе с аккаунтами и активностями. |
| Каталог ↔ страницы площадок | Выбор активности открывает её список; карточка ведёт обратно и позволяет перейти к другой активности. |
| Карта ↔ API | Панорамирование и масштабирование вызывают запрос видимой области с тем же фильтром активности. |
| Аккаунты ↔ новые страницы | После входа переходы через каталог и карточку, обновление страницы и возврат в свой профиль сохраняют пользователя; после выхода площадки остаются публичными. |

При проверке найдено и исправлено поведение связывания query-параметров: значения по умолчанию в свойствах класса не делали параметры страниц необязательными для Minimal API. Теперь значения заданы в конструкторе `LocationQuery`; запрос без явного номера страницы покрыт тестом.

## Проверки

Итог: **45 интеграционных тестов backend прошли, 0 ошибок, 0 пропущено; 4 теста геометрии карты прошли.** Включена регрессия аккаунтов и каталога. Backend собран без предупреждений и ошибок, TypeScript и production-сборка frontend прошли.

Дополнительно на отдельной пустой базе применены все три миграции, затем команда миграции повторена. Получены 4 активности, 2 локации и 6 связей без дублей. EF Core не обнаруживает изменений модели вне миграций. `docker compose config --quiet` проходит.

В Edge через Playwright пройдены настоящие пользовательские действия с живым API и PostgreSQL:

- Выбор спорта, список, выбор места, карточка, источник и время обновления.
- Смена активности с сохранением ID места.
- Выбор маркера, масштабирование и панорамирование клавиатурой с запросами нового bbox.
- Отказ тайлов: адреса, список и карточка остаются доступны.
- Пустой ответ списка, сетевой отказ API, отдельный повтор списка и меток.
- Неизвестные маршруты активности и площадки.
- Список и карточка на ширинах 360, 768 и 1440 без горизонтальной прокрутки. Снимки интерфейса просмотрены визуально.
- Старые сценарии регистрации, входа, выхода и профиля, включая сетевые ошибки и истёкшую сессию.

В проверенных сценариях нет необработанных ошибок JavaScript или неожиданных ответов локального API 5xx. Отрицательные сценарии обрабатывают ожидаемые 400/404/405/503.

## Границы проверки

Исходящий сетевой доступ браузера в этой среде запрещён. Реальная доставка тайлов OpenStreetMap не подтверждена: проверены обработка отказа, геометрия, маркеры и запросы области. С явно подставленным тестовым изображением дополнительно подтверждены загрузка тайлов без fallback, две метки из живого API, масштабирование и перетаскивание мышью. Это не проверка доступности внешнего сервиса.

Координаты начальных мест ориентировочные. Источники и степень подтверждения описаны в [документе о данных](location-sources.md).

Проверка проводилась через Vite, ASP.NET Core и отдельный локальный PostgreSQL. Контейнеры, nginx и удалённый CI в этой среде не запускались. CI дополнен тестами геометрии и проверкой списка локаций через nginx при контейнерном запуске.
