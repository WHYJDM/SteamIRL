# Аккаунты и профили: реализация и проверка

Дата: 2 ноября 2026 года. Область: US01 и US02 из BA, основа приватного аккаунта и публичного профиля. Это продолжение [проверки основы](foundation-verification.md).

## Реализованное поведение

- Регистрация создаёт аккаунт и публичный профиль атомарно и сразу выполняет вход.
- Email уникален без учёта регистра. Повторная и конкурентная регистрация не создают второй аккаунт.
- Вход использует единое сообщение при неизвестном email, неверном пароле или временной блокировке.
- Личный кабинет показывает свой email и позволяет менять псевдоним. Публичный профиль содержит только ID и псевдоним; он доступен без авторизации.
- Пароль хешируется ASP.NET Core Identity. Сессия хранится в HttpOnly cookie; секреты не помещаются в localStorage.
- Изменяющие запросы защищены CSRF-токеном. Нельзя выбрать другого владельца в запросе изменения профиля.
- После выхода обновление страницы не восстанавливает вход. После истечения сессии попытка сохранить профиль переводит интерфейс к предложению войти.
- Ошибка сети показывается в форме, поля сохраняются и повторная отправка доступна.

## Автоматические проверки

`dotnet test SteamIRL.sln`: **17 пройдено, 0 ошибок, 0 пропущено**, реальный отдельный PostgreSQL 17 на порту 55433.

В дополнение к шести проверкам основы добавлены одиннадцать проверок аккаунтов: регистрация/хеш/приватность, регистронезависимый дубль email, конкурентная регистрация, ошибки полей, CSRF, выход и повторный вход, единая ошибка авторизации, временная блокировка пароля, права изменения профиля и запрет подмены ID, ограничение частоты, анонимная сессия и отсутствующий профиль.

Production-сборка React и проверка TypeScript прошли. Сборка .NET прошла без предупреждений и ошибок. EF Core сообщает об отсутствии изменений модели вне миграций. Конфигурация Compose прошла `config --quiet`.

При проверке обнаружен и исправлен случай, когда отклонение неизвестного поля JSON возвращало 500 через общий обработчик. Теперь некорректные запросы возвращают 400; случай подмены ID покрыт тестом.

## Проверка пользовательских сценариев в браузере

Использован установленный Microsoft Edge в headless-режиме под управлением Playwright. Выполнены действия через настоящие поля, кнопки и ссылки с живыми React, API и PostgreSQL. Снимки мобильной регистрации и настольного профиля дополнительно просмотрены визуально.

| Сценарий | Результат |
| --- | --- |
| Регистрация и автоматический вход | Работают, открывается свой профиль |
| Несовпадающее подтверждение пароля | Показана ошибка, аккаунт не создаётся |
| Повторная регистрация email | Понятная ошибка в форме |
| Неверный пароль, затем правильный | Ошибка, затем успешный вход |
| Обновление страницы после входа | Сессия и собственный профиль сохраняются |
| Изменение псевдонима и обновление страницы | Новое имя сохранено в базе |
| Публичная страница в отдельном гостевом браузерном контексте | Доступна, email не отображается |
| Выход и последующее обновление страницы | Пользователь остаётся гостем |
| Удаление сессионных cookie перед сохранением | Приватный профиль скрывается, предлагается войти |
| Имитация сетевого отказа перед отправкой регистрации | Показана ошибка; значения полей сохранены; повтор после восстановления связи успешен |
| Вход клавишами Tab и Enter | Работает; фокус виден |
| Несуществующий профиль | Показано сообщение «Профиль не найден» |
| Страницы каталога, входа, регистрации, личного и публичного профиля на ширинах 360, 768, 1440 | Горизонтальной прокрутки нет |

В основных сценариях не обнаружены необработанные ошибки JavaScript или HTTP 5xx. Ожидаемые ответы 400/401/404/409 на отрицательные сценарии обработаны интерфейсом. Тестовые аккаунты имеют адреса в домене `example.test`; реальные email и письма не используются.

## Границы проверки

Актуализация 12 ноября 2026 года: GitHub-репозиторий теперь подключён и workflow запускался. Утверждения следующего абзаца про неподключённый репозиторий и непроверенный удалённый Actions сохраняются только как границы исторического прогона; container job последнего опубликованного запуска был пропущен после ошибки backend.

Проверка выполнена через Vite-прокси на `http://localhost:5173`, API на 5080 и отдельный локальный PostgreSQL. Контейнерный запуск, nginx, публичный HTTPS-деплой и удалённый GitHub Actions ещё не проверены: Docker Engine недоступен в текущем окружении, GitHub-репозиторий не подключён.

Регистрация/вход и профиль готовы в описанном объёме. Восстановление пароля, подтверждение email, экспорт/удаление данных из US19 и модерация аккаунтов ещё не реализованы. Полная независимая проверка безопасности и доступности в эту итерацию не входит.

Подход к cookie-аутентификации и CSRF опирается на [документацию ASP.NET Core](https://learn.microsoft.com/en-us/aspnet/core/security/anti-request-forgery?view=aspnetcore-10.0). API использует [ответы 401/403 вместо переадресации](https://learn.microsoft.com/en-us/aspnet/core/security/authentication/api-endpoint-auth?view=aspnetcore-10.0).
