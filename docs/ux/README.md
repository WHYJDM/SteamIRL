## Как пройти прототип

Открыть панель «Сценарии и альтернативы» (на узком экране свёрнута). Выбор J1/J2/J3 сбрасывает пример и задаёт предусловия вошедшего участника. В шапке можно показать демонстрационный вход; настоящие учётные данные не вводятся.

1. **J1:** карточка → «Позвать игроков сейчас» → параметры → предпросмотр → подтверждение публикации. Попробовать 0 игроков, неправильное время Planned, потерю связи, уже существующее приглашение и отмену с отказом/подтверждением.
2. **J2:** каталог → площадки/игры → карточка → явное подтверждение → один отклик → выход. Альтернативы: Full, Cancelled, Expired, нет связи. Гость возвращается после демонстрационного входа к исходной игре без автоматического вступления.
3. **J3:** площадка → исправление с обоснованием → Pending → переключение на модератора → решение с причиной → история автора. До одобрения публичный адрес прежний; после — предложенный. Устаревшее одобрение запрещено, остаётся обоснованный отказ.

«Следующий результат действия» — инструмент тестировщика, не элемент будущего продукта. Выбранная ошибка применяется один раз при соответствующей отправке: Full/Cancelled/Expired — вступление; Duplicate — создание; Stale — исправление/решение; Network — любой из этих запросов. «Сбросить пример» очищает состояние. Никаких HTTP-запросов, cookies, localStorage и реальных публикаций нет; учебные данные находятся только в памяти страницы.

Библиотека показывает состояния кнопок/фокуса, поля, inline-ошибки, статусы, карточки и обратную связь. У декоративных примеров кнопок нет бизнес-действия; основные сценарии выполняются на соответствующих экранах.

## Важные различия

- Скриншоты `assets/` — фактическое приложение, снятое с живым API/БД на учебных записях `[ДЕМО UX]`.
- Автономный прототип — целевой UX с отмеченными доработками: inline-ошибки/фокус, крупные цели, возврат после входа и восстановление рядом с ошибкой. Они не объявляются уже реализованными в основном приложении.
- P1 — один письменный ответ из BA; персоны — гипотезы. **Тест с пятью людьми ещё не проведён.** Автоматические проверки не являются результатами пользователей и не подтверждают NFR02/KPI.
- Полные BA-границы проекта сохранены в `docs/ba-traceability.md`; критерии БД и UX — в `docs/assessment-requirements.md`. Прошлый комплект БД не заменён и не удалён.

## Регенерация в полном проекте

Из корня проекта: `node scripts/build-ux.cjs` пересобирает редактируемый HTML и таблицу контраста; `node scripts/build-ux.cjs --pdf` дополнительно печатает PDF и проверяет число страниц/перекрытия. Для экспорта нужен локально установленный Playwright и Chromium/Edge; при другом расположении задать `STEAMIRL_PLAYWRIGHT_MODULE` и `STEAMIRL_BROWSER_PATH`. В текущем окружении используется локальный кеш Playwright, зависимость в приложение не добавлялась.

`node scripts/verify-ux.cjs` проверяет автономные сценарии и PDF. Готовый PDF и прототип открываются без этих инструментов. Обычная печать `specification.html` в PDF также возможна: A4, поля 0, фон включён, колонтитулы браузера выключены; после неё нужно проверить вёрстку.
